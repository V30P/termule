# Contributing

Thank you for your interest in contributing to Termule!

## Guidelines

Termule is built on keeping things simple and low dependency. I am incredibly appreciative of anybody who wants to help the project grow, but at the same time it is important to make sure that growth doesn't creep out of control. For this reason, I request that contributions respect the scope and structure of the project. I have personally considered deeply every dependency that I add to the SDK, and would appreciate if others did the same.

Hopefully you find this mindset reasonable. If you have any questions about contributing, please feel free to reach out!

## Opening Issues

If you have a question, problem, or suggestion, feel free to open an issue and I will take a look at it whenever I can.

For questions:
- Check the relevant documentation first

For problems:
- Provide as much context as possible
- Don't hesitate to propose fixes

For suggestions:
- Make sure the suggestion aligns with the goals of the project
- Include images, diagrams, etc. to explain your idea

## Pull Requests

If you have made a change or addition to Termule that you think belongs in this repo, you can open a pull request. Assuming that I agree it is worthwhile addition to the SDK, I will merge it *as long as*:

- It builds without errors *or* warnings
- All tests pass
- It aligns with the [guidelines](#guidelines)
- You have included sufficient documentation (whether through XML doc comments or a README / equivalent)
- The style is reasonable

If one or multiple of these things is not true I will have to ask you to update the PR, so for the best chance of getting your work merged quickly please try to keep these in mind.
